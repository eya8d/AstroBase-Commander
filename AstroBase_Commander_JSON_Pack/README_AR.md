# AstroBase-Commander — حزمة ملفات JSON

## محتويات الحزمة
- `data/game_config.json`: إعدادات اللعبة، مدة المهمة، واحتمال ظهور الأحداث.
- `data/resources.json`: تعريف الموارد وقيم البداية والاستهلاك.
- `data/systems.json`: أنظمة القاعدة وإنتاجها وتكلفتها.
- `data/events.json`: سجل مركزي للأحداث. كل حدث له `id` فريد.
- `data/nasa/solar_events.json`: سجل الحدث الشمسي التاريخي المرتبط ببيانات DONKI.
- `data/nasa/radiation.json`: قياسات RAD التي زودت بها في وصف المشروع.
- `data/nasa/event_thresholds.json`: عتبات التوازن الخاصة بالسيناريو التاريخي.
- `data/scenarios/scenarios.json`: خمسة سيناريوهات، تستخدم مراجع IDs ولا تنسخ تعريفات الأحداث.
- `data/mission_progression.json`: تقسيم الـ30 Sol ومكافآت المراحل.
- `data/achievements.json`: الإنجازات.
- `data/ending_rules.json`: شروط الفوز والخسارة.
- `data/ui/victory.json` و`data/ui/defeat.json`: بيانات شاشتي النهاية المتوافقة مفاهيميًا مع ملفات HTML المرفوعة.
- `data/data_sources.json`: قائمة مصادر البيانات.

## ملاحظات مهمة
1. الحزمة تحتوي 11 حدثًا في `events.json`: الأحداث الثلاثة الأصلية المذكورة، وثمانية أحداث إضافية، وحدث `radiation_burst` موجود ضمن الأحداث الأصلية. الحدث التاريخي DONKI ليس حدثًا عشوائيًا إضافيًا؛ إنه سجل تاريخي يشير إلى حدث اللعب `radiation_burst`.
2. الاحتمال `0.35` يعني احتمال إجمالي لظهور حدث عشوائي واحد في نهاية الـSol، وليس 35% لكل حدث.
3. الحدث التاريخي لعام 2017 يجب عرضه كسيناريو تاريخي، لا كتنبيه طقس فضائي مباشر أو بيانات حية.
4. قيم الموارد والتكاليف والعقوبات هي قيم توازن للعبة وليست مواصفات هندسية حقيقية.
5. قياسات RAD محفوظة بسياقها ووحدتها كما وردت في بيانات المشروع. لا تحولها إلى جرعة مريخية عامة.
6. كل `id` في السيناريوهات يشير إلى سجل مركزي. لا تنسخ تعريف الحدث داخل السيناريو.

## ترتيب تحميل مقترح في Godot
1. `game_config.json`
2. `resources.json`
3. `systems.json`
4. `events.json`
5. ملفات `nasa/`
6. `scenarios/scenarios.json`
7. `mission_progression.json`
8. `achievements.json`
9. `ending_rules.json` وملفات `ui/`

## ملاحظة دمج
ملف `server.js` المرفوع حاليًا يحتوي قيمًا تجريبية ثابتة مثل `[Value]` و`[Placeholder]`. ملفات JSON هنا تصف البيانات المطلوبة، لكنها لا تجعل Express يقرأها تلقائيًا. ستحتاج إلى تعديل `server.js` أو قراءة ملفات JSON من Godot وربط القيم الفعلية بحالة اللعبة.
